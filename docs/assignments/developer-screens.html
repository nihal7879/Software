What each piece does
The paperclip
Opens the modal in screen 2. Same button whether the lecture has an assignment or not — the modal decides which mode it is in.
The badge
Count of submissions with no mark yet. Hidden when zero. Turns into a green tick when every student on the lecture has been marked.
The strip under the topic
Only drawn when an assignment exists. Title, state, due date, and Mark →. It is the second way into marking, so the teacher never has to leave the row they are looking at.
Nothing else moves
Five columns stay five columns. The strip lives inside the Subject / topic cell, which is why the table still never scrolls sideways.
The assignment is not given from the check-in row. Confirm the lecture first, then use the paperclip. One place to set it, one place to change it — that is what keeps it simple.

Fields and rules
Goes to
Read-only. The students already on the lecture. An assignment can never be given to somebody who was not on it — that is how the group rule stays true.
The sheet
Required. PDF or image, 10 MB. Choosing a new file while editing replaces it for everybody, and the modal says so.
Title
Required. This is what the student, the parent and the marking queue all show — not the filename, which is usually something like ws7_final_v2.pdf.
Due date
Required. After it passes, the student sees Closed and cannot send. Only the teacher can re-open.
Out of
Whole number, default 10. A mark above it is refused on save.
Remove
Soft delete — is_deleted = TRUE. Files stay in storage; submissions already made are kept.
Editing after marks exist
Allowed. Changing the total re-checks every saved mark, and refuses if one would now be out of range.

How it is built
New submissions
Every submission with no mark, grouped by the day it was sent (not the day it was set), newest day first. A row leaves the list the moment it is marked.
Their answer, on the row
The file itself — name, size, Open and a download. The teacher can read the answer without leaving this list, which is how a queue gets worked through: read, decide, then Mark. Making them open the marking page first just to see the paper would defeat the point of having a queue.
Sheet
Opens the question paper for that assignment. Needed often — the teacher is reading an answer to a sheet they set a week ago.
Mark button
Goes straight to screen 4 with that student already selected, so the teacher does not have to find them in the list.
All assignments
One row per assignment, which means one row per lecture that has one. Shows the group note and the "same sheet elsewhere" note, so the separation is visible rather than surprising.
The three numbers
To mark · Still to come · Missed. The sidebar badge and the tab count both use To mark.
Admin sees it too
Same screen, not filtered to one teacher — for the admin it lists every teacher's assignments.

How it is built
Back
Returns to wherever marking was opened from — the Lectures tab or the Assignments tab. Store that on the way in.
The dot colours
Grey = nothing sent · Orange = sent, not marked · Green = marked · Red = closed with nothing sent. The saved mark shows beside the name once there is one.
Remark box
Minimum 190px tall and the full width of the pane. This is the one field that was cramped in every earlier draft, so it gets the space.
Marked sheet
Optional second upload — the teacher's corrected copy. When present, the student gets a third download button.
Save & next
Saves and jumps to the next student who has sent something and has no mark. On the last one it says so rather than jumping back to the top.
Save rules
A mark alone is fine. A remark alone is fine. Both empty is refused. A mark outside 0–total is refused. Re-saving keeps the first mark in the audit trail.
Nothing sent
The pane shows Send a reminder, and Re-open for everyone once the due date has passed.

Marking together — and when it is not allowed

Teacher & Admin

The rule in one line: the same sheet can be marked as a group only when the lecture itself was taken together. Handed out on another day to another student, it is a different assignment with its own marks.

The rule, precisely
An assignment belongs to a lecture
Not to a sheet, not to a subject. One lecture, one assignment — assignments.lecture_id.
All together is offered when
lecture.students.length > 1. Otherwise the toggle is not drawn at all and the amber note explains why.
Same sheet, another day
A second assignment row on that other lecture. Marks, submissions and the due date are all its own. The UI points this out in three places — the modal, the All assignments list and the marking header — so nobody is surprised by it.
Save all
Validates every mark first. If one is out of range nothing is saved, and the message names the limit. Students with nothing sent are skipped, not saved as zero.
Why not merge them
Two students who sat different lectures were taught differently, on different days, and may have different due dates. Merging them would make one mark stand for two different pieces of teaching.

How it is built
Order
To do first, then closed, then sent, then marked. Inside each, by due date. The thing that needs doing is always at the top.
Three downloads
Sheet — the question paper, always. My answer — their own upload, once sent. Marked copy — the teacher's corrected file, only when one was attached.
Replace
Allowed until the due date. It clears any mark, because the work has changed and has to be looked at again. The old file is kept as an earlier version.
Closed
After the due date the Send button is gone, and the server refuses an upload too. Only the teacher's Re-open brings it back.
No remark
An em dash in the remark column. Not "no remark given", which reads like something is missing — it is the normal case.
Never another student
The list is built from this student's own rows, and every download checks ownership on the server before a link is handed out.

How it is built
Five columns, no buttons
There is nothing for a parent to press. That is the design, not an omission.
Sent
Three states only — Sent on time, Sent late, Not yet, and Not sent once it closes. No file name, no time of day.
The three numbers
Sent · Average mark · Not sent. "Not sent" is the one that starts a conversation at home, which is the point of showing a parent anything.
The remark
Word for word what the teacher wrote — the same text the student sees. Written once, read by both.
The server agrees
A parent account asking for a file is refused with the same answer a stranger gets. Hiding the button is not the protection.

Data, storage and the rules

Developer

What has to exist behind those screens.

-- Every delete is a soft delete, like everything else in this system.

assignments
  id, lecture_id, title VARCHAR(160), due_date DATE, total_marks SMALLINT,
  file_key VARCHAR(255), file_name VARCHAR(255), file_size INT,
  reopened_at DATETIME NULL, created_by INT, created_at, is_deleted

assignment_submissions
  id, assignment_id, student_id,
  file_key, file_name, file_size,
  submitted_at DATETIME, is_late TINYINT(1),
  version SMALLINT,           -- a replaced answer is a new version, the old row is kept
  is_deleted
  UNIQUE (assignment_id, student_id, version)

assignment_marks
  id, assignment_id, student_id,
  mark DECIMAL(5,2) NULL,     -- NULL is allowed: a remark with no mark
  remark TEXT NULL,           -- NULL is the normal case
  marked_file_key VARCHAR(255) NULL, marked_file_name VARCHAR(255) NULL,
  marked_by INT, marked_at DATETIME, is_deleted
  UNIQUE (assignment_id, student_id)

assignments/<assignment_id>/brief/<uuid>.pdf
assignments/<assignment_id>/submissions/<student_id>/<uuid>.pdf
assignments/<assignment_id>/marked/<student_id>/<uuid>.pdf
Rules the server enforces, not the screen
One per lecture
UNIQUE (lecture_id) on live rows. The group rule falls out of this: students marked together are the students on that lecture, and nothing else can reach them.
Only its own students
A submission is refused unless that student is on that lecture.
Closed means closed
An upload after due_date with no reopened_at is refused by the API, not only hidden in the UI.
Late is decided on the server
is_late is computed from the server's Dubai clock at the moment it lands — never from anything the browser sends.
Mark or remark
Both empty is a 400. A mark outside 0–total_marks is a 400. Changing a saved mark writes an audit row carrying the old one.
Who may open a file
The student who owns it · the teacher of that lecture · an admin. Nobody else, and not the parent. Checked per request, before any link is made.
Links expire
Presigned: 5 minutes to upload, 60 seconds to read. Made fresh every time, never stored. A stored link outlives the permission it was granted under.
Files are renamed
Stored under a UUID; the real name lives in the database. Two answer.pdfs would otherwise overwrite each other, and a crafted name could write somewhere it should not.
The app cannot delete
The IAM user has PutObject and GetObject only — no DeleteObject, no ListBucket. A removed assignment is hidden, never destroyed.
Validation
zod on every body. PDF and common image types, 10 MB, checked again on the server after the upload lands — the browser's claim about a file is not evidence.
Still to decide. Should a photo of handwritten work be allowed as well as a PDF? It changes the student's upload on a phone more than anything else here, so it is worth answering before the work starts rather than after.
